# 设计画布性能优化与复测

针对此前审计中的空画布缩放、选区启动、大编组拖动、图片快照和 GPU 同步阻塞，已完成编辑器及 2D 渲染器的实现调整。六组复测共 **419 个匹配阶段、12,486 次动作采样**，另有 20 个交互回归阶段；原始基线保留。

## 实测结果

单位为 ms。同一台机器、Chromium 154、1280×720 浏览器视口，编辑器有效画布为 785×606，默认 DPR 1；硬件为 i5-12600KF、约 32 GiB 内存、GTX 750 Ti / ANGLE D3D11。DPR 2 使用测试页面覆盖输入后执行双倍 backing-store 绘制。

| 场景                                   | 指标               |        优化前 |     优化后 |
| -------------------------------------- | ------------------ | ------------: | ---------: |
| 空白画布连续缩放，三轮                 | rAF p95            |     66.6–77.9 |  11.1–11.2 |
| 空白画布连续缩放，三轮                 | rAF max            |    94.5–127.8 |  11.2–16.7 |
| 60 次空画布缩放输入                    | 相机提交次数       |           120 |         60 |
| 10,000 节点全选后开始拖动              | 同步事件耗时，单次 |        2471.2 |        4.0 |
| 10,000 节点整体拖动                    | rAF p95            |         699.9 |       11.2 |
| 5,000 子节点编组，带吸附拖动           | rAF p95 / max      | 266.7 / 605.5 | 5.7 / 11.1 |
| 1,000 混合节点、内嵌图片，三轮松手提交 | 单次 rAF 间隔      | 1455.4–1777.8 |  11.1–16.7 |

| 10,000 密集节点缓存平移                | 引擎同步动作 p95   |           1.6 |        0.6 |

额外复现了原审计中未能完成的 **5,000 节点内嵌图片文档**：拖动启动 1.0 ms；拖动 rAF p95 11.0 ms、max 44.5 ms；松手同步提交 3.7 ms、rAF 22.3 ms。完成 pointercancel、Escape、回到原点不产生历史记录、手势缩放保护与锚点缩放断言。冷挂载阶段总时长 1308.7 ms，其中额外细化尾延迟 1101.5 ms。图片首次显示的成本仍存在。

缓存长距离平移保持在预算内：瓦片最高 134,118,400 字节（128 MiB 预算内），节点位图约 65.7 MB（64 MiB 预算内）；卸载后瓦片字节、节点位图字节、图片数量和节点资源引用均归零。另完成 20 次创建、绘制及释放。

## 具体改动

1. **把相机从整个编辑器的 React 更新中分离。** `CanvasViewportSource` 只驱动渲染表面、标尺和倍率文字。先同步舞台边界、缩放 CSS 与实际滚动位置，再发布一次相机；重复滚动通知被去重。选区 DOM 使用 CSS 缩放变量，避免随每个相机输入重建节点与侧栏。
2. **去掉手势中的深拷贝和整页序列化。** 历史记录共享不可变项目；手势保留原快照，提交时跳过引用未变的节点，只比较实际变化。图片字符串不再因拖动开始、松手比较或入历史而复制。显式导出与复制仍保留需要的数据隔离，图片字段及项目格式兼容。
3. **替换大选区和吸附的低效算法。** 节点数组用 WeakMap 缓存 ID/子节点邻接索引；后代遍历不再反复扫描整页。根选区用 Set 与祖先结果缓存，吸附目标按手势排序后用二分查找。超过 200 个选中节点时只画整体边界。
4. **增加保持图层顺序的拖动预览。** 将场景拆成最多八个交错的静止/移动层，共享空间索引，通过相机平移复用纹理。移动过程中不编译场景、不更新整页 React 状态；松手只提交一次。外部裁剪、外部变换父级或依赖背景的混合模式进入兼容路径。取消操作清除预览并恢复原画面；位移取整保持原节点小数坐标。
5. **给栅格工作分帧，并复用缩放缓存。** 每帧约 6 ms 软预算，每八个条目检查截止时间；使用版本号丢弃过期绘制任务。新分辨率块完成前，按目标区域裁切复用较低分辨率块，避免透明区域重复叠加。位置变化复用节点文字布局和位图资源。
6. **减少 GPU 同步等待。** 上传后使用 fence，在后续帧确认完成后再检查 GPU 错误；上传异常与上下文丢失仍切到 Canvas2D。移动图层使用预乘 alpha 混合，覆盖层的选框与原型标记同步平移。

主画布依然是 **Canvas2D 节点栅格化 + WebGL2 瓦片合成**，没有引入 3D 渲染，也没有将文字、路径改成 GPU 矢量引擎。

## DPR 与质量取舍

1,000 个效果节点、模拟 DPR 2、99%→101% 缩放三轮：同步调用由 105.4–112.8 ms 降到 0.7–0.9 ms。这个数字不能全归因于 fence：优化后为旧/新档位及交互层预留预算，在该视口保留 2 倍采样缓存，避免原先跨到 4 倍采样档位。该阶段从 150 个瓦片重画/上传变为零次。

因此，此项结果同时体现缓存复用和采样策略变化，不是同样 150 次上传的吞吐量提升。需要的采样率约为 2.02，而保留采样率为 2；极大视口或多层交互时也可能按预算降低采样倍率。常用倍率、透明接缝和移动图层经过像素对照，但没有据此宣称所有倍率与文档都逐像素一致。

## 仍然较重的场景

- **大子树全量更新仍非恒定成本。** 直接通过引擎每帧替换 5,000 节点子树的同步 p95 为 73.1 ms（原 94.2 ms），rAF max 122.1 ms。编辑器拖动走缓存预览，结构更新、复杂兼容路径仍可能触发此类工作。
- **一次性大提交仍会有长帧。** 10,000 节点整体拖动结束的单次 rAF 为 72.3 ms；5,000 子节点编组松手为 88.8 ms。这两项没有得到和持续拖动同等幅度的改善，后者此次样本比原 49.9 ms 更慢，不能标记为已消除。
- **复杂图片缩放仍有尖峰。** 5,000 个 URL 混合节点缩放此次最大间隔为 177.7 ms；10,000 个混合节点缩放 p95 为 33.5 ms、max 44.6 ms。首次解码、文字和效果绘制仍在主线程，单个 GPU 或绘图调用可能超过软预算。
- 冷区域和新分辨率内容渐进出现，6 ms 是调度目标，不是硬上限。没有实现 Worker 栅格化、完整组隔离合成、独立资产数据库或历史差量存储。

## 验证与数据口径

- 核心与渲染器 **35 项单元/集成测试通过**。
- 浏览器 **39 项像素及渲染行为检查通过**：小数缩放、路径、文字、裁剪、混合、阴影、删除、透明接缝、异步图片、文字编辑、GPU 丢失回退，以及两种后端的移动层、移入视口节点、选框和原型标记对齐。详见 [检查输出](2026-10-04-optimized-visual.txt)。
- 真实编辑器 165 个性能阶段含几何提交、撤销/重做及文字输入结果断言；额外 [20 个交互回归阶段](2026-10-04-optimized-interaction.json) 覆盖取消、无效移动和缩放。
- Web、renderer 和性能入口 TypeScript 检查通过；正式 Web 生产构建及性能页生产构建通过。性能页聚合全部测试模块产生大块提示，正式应用构建通过。未运行 lint。
- 构建与 Vite 缓存放在系统临时目录；未执行 pnpm。没有修改或保存测试使用的用户项目。

`action` 只统计同步动作；`intervals` 是 rAF 回调间隔，**不是 GPU 完成时间、屏幕 FPS 或真实 INP**。单次操作只有一个样本，不能当作稳定分位数。连续交互使用合成指针/键盘事件，真实处理器、React、几何和渲染路径参与测试。

优化后测量在原三帧收尾之外等待 `data-pending-tiles` 归零，记录 `completionTailMs`，完整等待计入 `elapsedMs`。优化前没有这一额外等待。因此冷启动不能只比较同步首帧；总时长包含不同收尾规则，也不是精确的首屏呈现时间。后台负载未做到实验室级隔离，本机单轮结果不应作为所有设备的性能承诺。
