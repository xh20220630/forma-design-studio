# 2D 画布渲染架构

主编辑画布使用保留场景、局部失效和分块 GPU 合成。采用 Figma 公开架构中的场景与界面分离、分块复用、显式资源管理思路，没有引入 3D 场景或透视相机。

## 数据流与职责

`React 文档提交 → SceneCompiler → 空间索引/变化范围 → TileCache → CanvasPainter → WebGL2Compositor`

连续平移与缩放走独立的 `CanvasViewportSource`。标尺、渲染表面和倍率文字局部订阅相机，编辑器根组件不随每次滚动重新渲染。舞台尺寸、CSS 缩放和原生滚动位置一次更新后再发布相机，避免同一次缩放产生两次相机提交。

拖动优先走 `beginTranslation → translate → endTranslation`：共享场景索引，按原绘制顺序分出静止层与移动层，通过相机偏移复用块。移动过程中不重新编译节点，也不向 React 提交整页。松手后生成一次不可变文档；取消时丢弃预览。外部裁剪、外部父级旋转、依赖背景的混合模式或超过八个交错层会回退到普通文档更新，保留绘制语义。

选框、辅助线和网格经过独立的 `overlay.ts`，不使内容缓存失效。GPU 不能使用时，`Canvas2DCompositor` 合成同样的块。节点仍由 Canvas 2D 栅格化；WebGL2 负责已缓存块的纹理上传、采样与显示，并非全矢量 GPU 引擎。

| 模块                 | 职责                                                             |
| -------------------- | ---------------------------------------------------------------- |
| `CanvasRenderer.tsx` | React 提交桥接、内容/GPU/覆盖表面、临时输入框之外的画布入口      |
| `scene.ts`           | 保留解析结果与组件子节点；叶节点快速更新；结构变化时重新解析层级 |
| `geometry.ts`        | 世界/局部坐标转换；可增删的网格索引；大节点独立分桶              |
| `tiles.ts`           | 世界坐标分块、缩放分辨率、采样边缘、损伤区域、LRU 预算           |
| `painter.ts`         | 现有路径、文字、图片、效果绘制及节点资源引用计数                 |
| `compositor.ts`      | WebGL2 纹理复用和 Canvas 2D 回退；GPU 资源释放                   |
| `overlay.ts`         | 编辑辅助绘制；只处理选中、悬停和原型提示条目                     |
| `translation.ts`     | 保持绘制顺序的手势分层、共享空间查询与大选区边界                 |
| `engine.ts`          | 编译提交、帧合并、点击/框选、资源失效与后端切换                  |

## 更新与缓存规则

- 文档以不可变节点数组提交。相机与选区更新复用场景；不得原地修改节点对象。
- 撤销历史共享不可变快照。手势开始不深拷贝图片数据，提交只比较变化节点，避免整页 `JSON.stringify`。显式导出和复制仍保留所需的数据隔离。
- 层级索引按不可变节点数组缓存；后代遍历使用邻接表。根选区用集合与祖先记忆化过滤，吸附点按手势预排序后用二分查找。
- 普通叶节点的位置/样式变化只重新计算该节点、更新其索引条目。父级、顺序、可见性、实例与其他结构变化进入完整层级解析，仍复用未变化的记录和索引条目。
- 新文档快照仍需比较节点引用，复杂结构修改仍可能遍历整个场景；当前不是完全常数时间的文档更新协议。
- 编译器返回的空间索引是当前场景的活动索引，不可作为历史快照保留。编译只在 React 提交后执行，避免中止的 React render 改变正在使用的命中数据。
- 移动、删除、样式及排序变化会失效旧/新边界对应的块。边界包含描边、阴影、模糊扩展；大批量变化统一失效，限制失效计算量。
- 每块有效区域为 256×256 像素，四边各有 2 像素采样边缘。背景与节点在同一块内合成，保留混合模式的背景语义。
- 缩放使用 2 的幂次分辨率，平移不改变块的世界坐标 key。物理像素边界由两种后端共用，避免小数缩放的接缝。极大视口按预算降低块采样倍率，避免当前可见块互相驱逐。
- 栅格任务按约 6 ms 的软预算分帧，每八个条目检查截止时间。未完成的块继续细化，缩放时优先裁切复用已有低分辨率块；冷区域可能逐步出现。单个昂贵节点或驱动调用仍可能超过预算，不能把一次 `draw()` 返回当作整幅图已完成。
- GPU 上传后用异步 fence 检查完成状态，再检查错误，避免每帧立即读取错误状态造成驱动同步等待。上下文丢失和上传异常仍触发回退。
- 大于 200 个选中节点只绘制整体选区边界，避免逐个绘制大量几乎重叠的选框。
- 块位图和 GPU 纹理合计估算预算为 128 MiB；节点位图另有 64 MiB 预算。浏览器内部缓冲、图像解码、路径和字体对象不包含在此估算内。可见表面沿用 DPR≤2、单边≤8192、1600 万像素限制。
- 图片完成加载时只失效使用该资源的块与节点位图。字体加载使文字/位图与块缓存失效。引用归零、LRU 驱逐和卸载都会释放相应资源。
- GPU 初始化或上传失败、上下文丢失会切换到 2D 合成。当前会话保持回退，避免不稳定设备反复切换。跨域污染图片不能上传 GPU 时也通过此路径显示。

## 验证

仓库根目录运行（使用已安装的 Node 与工作区依赖）：

```powershell
node --test packages/renderer/tests/unit/*.test.ts packages/renderer/tests/integration/*.test.ts
node packages/renderer/node_modules/typescript/bin/tsc --noEmit -p packages/renderer/tsconfig.json
node apps/web/node_modules/typescript/bin/tsc --noEmit -p apps/web/tsconfig.json
node apps/web/node_modules/vite/bin/vite.js --config packages/renderer/tests/browser/vite.config.ts
```

打开 `http://127.0.0.1:5187/`，执行画面检查与一万节点基准。此独立页面不读写用户项目，开发缓存放入系统临时目录。画面检查比较分块输出与直接节点绘制，覆盖小数缩放、路径、文字、裁剪、混合、阴影、删除与 GPU 丢失回退。基准统计一万个可见矩形的首次编译、首次绘制、缓存平移和单节点编辑；时间是 CPU 绘制/提交耗时，不代表 GPU 完成时间或 FPS。

主画布的 `data-backend`、`data-rasterized-tiles`、`data-rasterized-nodes`、`data-texture-uploads`、`data-tile-cache-bytes`、`data-pending-tiles` 与 `data-frame-time-ms` 用于检查每次内容帧的实际工作量。覆盖层更新不增加 `data-render-count`。

完整编辑器、引擎、图片快照、DPR 压力及资源释放的基线与优化对比见 [性能优化复测](performance/2026-10-04-optimization.md)。复测额外等待待绘制块归零，单独记录分帧完成尾延迟，避免将延后绘制误报为完成加速。35 项核心与渲染器单元/集成测试通过；浏览器像素检查覆盖 GPU 回退、透明接缝、异步图片、文字编辑、拖动分层、视口外节点移入、选框与原型提示对齐。

## 能力边界

首次生成分块、文本测量、路径与效果绘制仍在主线程；尚未实现 Worker、WebGPU、独立字体引擎和完整的组隔离合成。当前文字/效果语义与原 Canvas 绘制器保持一致。缩略图、原型与导出继续使用 DOM/SVG，不保证与画布逐像素一致。

后续可通过同一场景与合成接口替换节点栅格后端；应根据复杂文字、图片和效果文档的测量结果推进，不将简单矩形基准推广到所有文档。
