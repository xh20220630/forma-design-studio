# 本地 Agent 请求错误排查

## 已确认案例：Codex CLI 版本与模型目录不匹配

记录日期：2026-10-03。

- 场景：通过本地 Codex 连接向设计助手发送“你好”。CLI 默认配置为 `gpt-6.1-sol`，使用 ChatGPT 账号登录。
- 原始上游错误：HTTP **400**，`invalid_request_error`，`The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account.`
- 当时 CLI 版本：`0.154.0`。其 `model/list` 目录没有 `gpt-6.1-sol`。
- 修复验证：更新至 `0.160.0` 后，同一账号、同一模型配置的目录包含 `gpt-6.1-sol`，桥接请求和连接测试均成功。

该案例说明旧 CLI 的模型目录可能尚未包含新模型。错误文字中提到 ChatGPT 账号，并不能单独证明账号永久无权使用该模型。应结合实际 CLI 版本、目录和请求结果判断。

## 用户排查步骤

1. 在聊天中的错误卡片确认出错连接、模型和**上游状态码**。Forma API 的 502 与上游的 400 分别记录。
2. 读取或刷新“可选模型”。Codex 使用本机 `app-server` 的 `model/list`，沿用当前 CLI 的登录环境，不硬编码模型名。
3. 点击“切换”保存当前任务通道的模型，再重新发送消息。切换不自动重放原操作；历史错误和已完成动作继续保留。
4. 如果预期模型缺失，运行 `codex --version`。通过 npm 安装的 Codex 可运行 `npm install -g @openai/codex@latest`，完成后刷新目录。
5. 如果目录读取失败，检查 CLI 登录、版本和网络；如果模型仍被拒绝，检查账号或工作区权限，并复制错误记录排查。

其他 CLI 尚未提供桥接包可查询的模型目录时，界面明确说明限制，请先在该 CLI 中确认模型，再手动填写 ID。默认模型选项不作为已验证可用的替代模型。

## 已确认案例：参考图还原达到本地超时上限

记录日期：2026-10-03。

- CLI 已更新到 `0.160.0`，同一连接已成功生成并批准参考图。
- 两次还原分别于 20:52、20:57 失败，均记录“本地 Agent 请求超过 180 秒，已终止进程”。
- 还原停在参考图分析阶段，未获得草稿，素材清单仍为空。
- CLI 配置中的思考强度为 `xhigh`，旧桥接请求继承该配置，视觉分析与普通对话共用 180 秒的截止时间。

修复后，网页 Codex 连接默认指定 `medium`，可在连接编辑器选择 `low`、`high`、`xhigh` 或沿用 CLI 配置。视觉还原使用独立的 `reconstructionTimeoutMs`，默认 600000 毫秒；普通对话与生图仍使用 `timeoutMs`。超时会关闭进程并保留已确认图片与已完成素材，重试继续使用这些结果。

同一张 853 × 1844 参考图的隔离验证中，真实 Codex 视觉分析与结构校验约用时 180.5 秒，返回 1 个页面、127 个可编辑节点。该验证使用 `medium` 和 600 秒上限，素材生成以测试响应替代，未重新消耗生图额度，也未覆盖用户项目。

本地超时没有上游 HTTP 状态，不应当作 HTTP 400 模型权限错误。排查卡片显示“任务等待超时”、任务当前上限和思考强度，并提供连接设置入口；不自动读取模型目录。先确认简单对话与网络正常，再调整任务等待时间或思考强度，最后重试还原。

## 错误记录字段

API 在数据目录中的 `model-request-errors.json` 保存最近 200 条模型请求错误，包括记录 ID、连接、任务通道、请求模型、时间、上游状态、错误代码和脱敏说明。聊天失败消息同时持久化 `errorDetails`，更改设置后仍保留原请求快照。记录不保存请求正文、密钥或自定义请求头值。

只有原始说明明确指向不存在、不支持或无权访问模型时，才分类为 `model_unavailable`。其他 HTTP 400 分类为 `invalid_request`，提示检查参数和权限，避免误判为模型问题。本地截止时间归为 `request_timeout`，记录 `operation` 和实际 `timeoutMs`；其他网络或 CLI 启动失败归为 `request_failed`。

旧聊天中的该 Codex 错误可兼容显示排查卡片；当存在多个 Codex 连接而无法确认原连接时，不提供猜测的切换目标。原连接已删除或当前已使用另一连接时，应通过模型连接设置操作。

协议参考：[Codex app-server 模型目录](https://developers.openai.com/codex/app-server#models)。
